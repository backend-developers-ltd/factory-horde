# Behavioral acceptance controls

This development-only factory emits working, partially implemented or broken applications. Tasks naming `samplelib` receive a Python package with `mean` and `unique`; other tasks receive a persistent to-do CLI. The public hotkey's SHA-256 integer modulo three selects the variant, recorded in factory logs. Require all three variants in the acceptance cohort. Defective CLI documentation deliberately claims working features, so runtime evidence must outweigh claims. The library has neither `main.py` nor a README and exercises package imports, input validation and order preservation. The factory makes no model calls; each resulting project is evaluated by the production adaptive judge.

Put `library-task.json` alongside a to-do task JSON in the configured task directory to exercise both project types for every miner in one round. `python -m localnet.check_behavioral <immutable-control-image>` verifies working controls outrank defects, working libraries satisfy every requirement and working CLIs receive credit for deletion. Per-step decisions and captures are retained in `state/behavioral-round.json` for inspection.
